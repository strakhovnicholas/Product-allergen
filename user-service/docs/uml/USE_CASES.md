# Документирование прецедентов — user-service

## Документирование прецедентов

**UC-01 Управление профилем** — прецедент используется актором «Пользователь» для создания, просмотра, изменения и удаления медицинского профиля (аллергены, хронические заболевания, антропометрия). API: `/api/user/info`.

**UC-02 Учёт приёмов пищи** — прецедент используется при необходимости зафиксировать, что и когда было съедено. Пользователь указывает продукты, время и порцию. Данные сохраняются в PostgreSQL и используются анализатором. API: `/api/feelings/food`.

**UC-03 Учёт симптомов** — прецедент используется для фиксации аллергических и других реакций с привязкой ко времени. API: `/api/feelings/symptoms`.

**UC-04 Учёт самочувствия** — прецедент используется для ежедневной оценки состояния по шкале. API: `/api/feelings/common`.

**UC-05 Учёт лекарств** — прецедент используется для ведения справочника препаратов и фактов приёма. API: `/api/medicines`, `/api/feelings/medicines`.

**UC-06 Заметки** — прецедент используется для произвольных текстовых записей в дневнике. API: `/api/notes`.

**UC-07 Анализ корреляции «еда — симптом»** — прецедент используется пользователем или **analytics-service** при наличии данных за период. Система сопоставляет компоненты питания и симптомы в заданном временном окне (`symptomAppearanceTimeHours`) и возвращает список потенциальных триггеров. API: `GET /api/food-analyzer/analyze`.

**UC-08 Справочник продуктов** — прецедент используется для CRUD пользовательского каталога продуктов. API: `/api/food`.

**UC-09 Справочник симптомов** — прецедент используется для управления перечнем возможных симптомов. API: `/api/symptoms`.

**Проверка внутреннего токена шлюза** — прецедент выполняется `InternalGatewayFilter` для каждого запроса (кроме Swagger). Сравнивается заголовок `X-Internal-Gateway-Token` с `internal.api.secret`.

**Извлечение X-User-Id** — прецедент выполняется `UserIdArgumentResolver` для параметров `@CurrentUserId`, гарантируя привязку операции к аутентифицированному пользователю.

## Документирование отношений

Между каждым UC-01…UC-09 и **«Проверка внутреннего токена»** / **«Извлечение X-User-Id»** выбран тип **include**, так как без доверенного контекста от шлюза обработка запроса невозможна.

Между **«UC-07 Анализ еда—симптом»** и **«UC-02 Учёт приёмов пищи»** / **«UC-03 Учёт симптомов»** выбран тип **extend**: анализ активируется только при накопленных записях и расширяет базовый процесс ведения дневника, но не обязателен при каждом приёме пищи.
