## 2.4. Проектирование интерфейса пользователя (текст для диплома)

### 2.4.1. Цели и принципы проектирования UI

Клиентская часть программного комплекса реализована как кроссплатформенное мобильное приложение на **React Native (Expo)**. Интерфейс ориентирован на пользователей с пищевой аллергией и предназначен для ежедневного ведения дневника, просмотра отчётов и управления медицинским профилем.

При проектировании интерфейса были приняты следующие принципы:

- **единая визуальная система** — синяя hero-панель с круглой иконкой, белые карточки контента, скругления 16–24 px;
- **минимизация когнитивной нагрузки** — основные сценарии доступны из нижней панели навигации (4 вкладки);
- **контекстное редактирование** — добавление записей дневника без перехода на отдельные «пустые» формы (inline-редакторы в секциях);
- **доступность на мобильных устройствах** — крупные зоны нажатия, контрастные подписи, учёт safe-area;
- **согласованность с серверным API** — экраны регистрации и профиля отражают поля `user_info`, симптомов, питания и отчётов.

Цветовая палитра: основной акцент `#1D4ED8`, фон `#EEF4FF` / `#F8FBFF`, поверхности `#FFFFFF`, семантические цвета для риска и реакций (зелёный / жёлтый / красный).

### 2.4.2. Структура навигации приложения

Навигация построена на модели **вкладок (Tab Navigator)** и **стека (Stack)**:

1. **Неавторизованная зона:** вход (`/login`), регистрация (`/register`), шаги профиля (`/profile-step-1`, `/profile-step-2`).
2. **Основная зона (вкладки):** Дневник, Камера (сканирование), Отчёты, Профиль.
3. **Модальные экраны:** редактирование профиля (`/edit-profile`), устаревшие формы добавления записей (`/add-*`).

*Рисунок 2.X — Карта навигации мобильного приложения* (см. Canvas).

### 2.4.3. Проектирование экранов регистрации и онбординга

**Шаг 1 — регистрация.** Синяя верхняя панель с круглой иконкой «добавить пользователя», поля email/пароль, кнопка перехода к шагу 2.

**Шаг 2 — данные пользователя.** Панель с иконкой профиля; форма: имя, фамилия, **возраст (ползунок 5–100 лет)**, вес и рост (вертикальные пикеры), выбор пола (две кнопки). Соответствует полям `age`, `weight`, `height`, `gender` в API.

**Шаг 3 — привычки и здоровье.** Панель с иконкой аптечки; блоки «образ жизни» (курение, алкоголь, спорт) в виде карточек с выбором Да/Нет; теги хронических заболеваний и аллергий; завершение регистрации.

*Рисунки 2.X–2.X — Макеты экранов регистрации* (см. Canvas).

### 2.4.4. Проектирование экрана «Дневник»

Центральный экран приложения. Состав:

- **Hero-блок:** имя пользователя, краткое описание, сводка за выбранный день (число записей, питание, симптомы).
- **Навигация по дате:** переключение дня.
- **Секции-аккордеоны:** Самочувствие, Симптомы, Лекарства, Питание, Заметки — каждая с счётчиком и кнопкой «+».
- **Карточки записей:** компактный список с цветной полоской слева; для питания — теги категории/реакции; inline-редакторы при добавлении (по аналогии с редактором лекарств/симптомов).

*Рисунок 2.X — Макет экрана «Дневник»* (см. Canvas).

### 2.4.5. Проектирование экранов «Отчёты», «Камера», «Профиль»

**Отчёты:** hero с выбором периода и генерацией PDF; метрики; компактные строки истории отчётов и анализа продуктов.

**Камера:** захват фото этикетки, OCR состава, сопоставление с профилем аллергий (локальный анализ + при необходимости сервер).

**Профиль:** hero с аватаром-инициалом, метрики, блоки «Здоровье» и «Образ жизни», переход в редактирование, выход из аккаунта.

**Редактирование профиля:** секции с тегами (аллергии, хронические, предрасположенность), живые карточки привычек (как в дневнике).

## scan-service — черновик §2.3.5 (заменить ошибочный абзац)

Микросервис **scan-service** предназначен для серверной проверки продуктов по штрих-коду и кэширования данных из внешних каталогов (Open Food Facts). В MongoDB/PostgreSQL хранятся сущности `product_cache` (состав, название, источник) и `scan_history` (user_id, дата, результат оценки риска). Клиентское приложение дополнительно выполняет локальный OCR этикетки и экспресс-анализ состава на устройстве до обращения к серверу.
