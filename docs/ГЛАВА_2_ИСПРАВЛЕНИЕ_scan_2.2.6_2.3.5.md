## 2.2.6. Логическая модель scan-service (заменить абзац про «стадию проектирования»)

Микросервис **scan-service** реализует анализ состава продуктов питания и оценку аллергенного риска для пользователя.

В рамках сервиса используются следующие сущности:

- **product_cache** — кэш данных о продуктах из внешних источников (Open Food Facts);
- **scan_history** — история сканирований пользователя с результатом оценки риска.

Сущность **product_cache** снижает нагрузку на внешние API и ускоряет повторные проверки одного штрихкода. Сущность **scan_history** связывается с пользователем через **user_id** (UUID из auth-service).

## 2.3.5. Физическая модель scan-service (заменить дублированный текст про analytics)

Микросервис **scan-service** использует PostgreSQL (или комбинацию PostgreSQL и Redis для кэша) для таблиц **product_cache** и **scan_history**.

Таблица **product_cache** хранит штрихкод, наименование, текст состава, теги аллергенов и время истечения кэша. Таблица **scan_history** фиксирует **user_id**, штрихкод, уровень риска, список совпавших аллергенов и время сканирования.

Внешний источник данных — API **Open Food Facts**. Связь с профилем пользователя выполняется через REST-запрос к **user-service** (Feign через **gateway-service**), без прямого доступа к MongoDB user-service.
